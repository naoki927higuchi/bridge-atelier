## 1. 文書の位置づけ・適用範囲・記号・保証・管理原則

### 1.1 本書の位置づけ

- 本書は、市ヶ谷ビディング規約（Ichigaya Bidding System）の全条件を収録する完全リファレンスです。主要な規約を素早く引く実戦ガイドは [Bidding System](bidding-system.md) です。両文書で重要な条件が重複しても、意味は一致させます。
- 本書（日本語版）は、市ヶ谷ビディング規約の唯一の意味仕様の正本です。コールの意味・保証・義務は本書で確定します。
- 英語版は本書に従う公式翻訳です。英語版（[English](../en/bidding-reference.md)）と本書が食い違う場合は、本書が優先します。
- 実戦ガイド（[Bidding System](bidding-system.md)）は、本書の要点を素早く引くための文書で、規約の意味を追加しません。本書と食い違う場合は、本書が優先します。
- 実装（コード）は本書に従います。実装が本書と違う動きをする場合は、実装の不具合として扱います（既知の差異は [13.7](#137-規約と実装の既知の差異)）。
- 本書は、コールの**意味**（保証、義務、状態、未定義の境界）を定めます。CPUがどのコールを選ぶかの調整可能な閾値・係数・候補の得点は、原則として本書に含めず、実装（コード）で管理します。意味の理解に必要なCPUの目安だけを【CPU基準】として収録します。
- 本規約に従うことは、全局面での最適な結果や契約の品質を保証しません。
- 規約版・ビディングAIの版・ゲームの版は別々に管理します（[1.8](#18-改訂の手順)）。

### 1.2 適用範囲と系列の書き方

- 主な対象は、**相手の全コールがPassで、応答者が未パス**の通常のオークションです。
- 系列は自陣（N/S）のコールだけを書き、途中の相手のPassは省略します。席が回っても役割は同じです。
- 規約は**完全な文脈**で適用します。完全な文脈には、最初のPassの履歴、介入、オープニングの位置、すでに分かっている自然／人工の意味が含まれます。**コールの末尾が一致するだけでは適用しません。**
- 数値ビッドの順序は ♣→♦→♥→♠→NT です。オークションの終了には、競技規則上の連続したPassが必要です。
- **合法性と規約適合性は別**です。規約に合わないコールでも、競技規則上合法なら人間は宣言できます（[12.1](#121-人間の規約外コール)）。

### 1.3 三層の情報

| 層 | 意味 |
|---|---|
| **【保証】GUARANTEE（公開保証）** | 規約が確定する枚数、明示されたHCP、特定の札、義務。後の判断に引き継ぎ、矛盾を検出する |
| **【通常】通常目安** | 通常のHCP、典型的な分布、運用方針。厳密な下限・上限・否定の保証にはしない |
| **【CPU基準】CPU_ESTIMATE／CPU評価** | CPUが自分の手札と公開されたオークションから得る推定戦力、契約品質、候補の得点。通常範囲の中心は、後の限定的な応答などで更新してよいが、強い手の可能性を「選ばれなかったコール」だけを理由にゼロにしない |

- CPUは、自分の13枚と公開されたオークションだけを判断の入力にします。パートナー・相手の実際のカード、終了後の検証用の52枚、相手の判断理由を、隠れた情報源として使いません。
- パートナーの長さからストッパーの補完を期待するのは推定であり、A／Kの所持の保証ではありません。

### 1.4 意味の状態

| 状態 | 意味 |
|---|---|
| DEFINED | 定義済み |
| PARTIAL | 一部だけ定義 |
| UNDEFINED | 該当する定義がない |
| CONFLICT | これまでの保証・制約と矛盾 |
| UNSUPPORTED | 意味は定義済みだが、CPUが未対応 |

- 状態を一律にPassへ変換しません。
- 未定義のコールを自然と決めつけず、人工のビッドを自然な候補で代用しません。

### 1.5 解釈の優先順位

コールの意味は、次の順に照合します。

1. 進行中の専用の質問・報告
2. 完全な文脈に合う人工の開始・指定された自然な継続
3. 一般の自然な規約
4. 未定義

例：ジャコビー2NTのA所在報告としての4NTをブラックウッドとして扱わない。D系列（[6章](#6-人工fsf-ad確定後続)）の自然な4♣をガーバーとして扱わない。

### 1.6 記号・ラベル

| 記号・ラベル | 意味 |
|---|---|
| `M` | メジャー（♥／♠） |
| `m` | マイナー（♣／♦） |
| `x` | 任意のスート |
| `5+` | 5枚以上 |
| `HCP` | ハイカードポイント |
| `BAL` | バランス型（本書では1NTの手形 4333・4432・5332、5枚はマイナーのみ） |
| `NF`・`INV`・`F1`・`GF`・`TO PLAY` | 強制性（[2.1](#21-強制性の定義)） |
| `fit` | パートナーと合わせた枚数（例：8枚fit） |
| 【保証】【通常】【CPU基準】 | 三層の情報（[1.3](#13-三層の情報)） |
| 【未定義】 | 規約に定義がない |
| 【不採用】 | 規約として採用しないと明示されている |
| 【CPU未対応】 | 規約は定義済みだが、CPUが実装していない |

「規約ID」（D01、J02 など）は本規約の識別子です。IDのない規約は本書の節番号で参照します（[14章](#14-付録b規約id実装id対応索引)）。

### 1.7 管理原則

**人間が決めるもの**：コールの意味、公開保証、F1／GF、切り札合意、回答・終了の条件、適用範囲。

**実装が決めてよいもの**：同じ意味に適合する候補の得点、閾値、ログの書式、データの型、同じSEEDでの再現の方法。

- CPUの裁量で公開保証が変わる場合は、人間の判断へ戻します。
- 本書に記載のない事項は【未定義】として扱います。記載漏れが疑われる場合も推測で補わず、意味の追加は人間の判断によります。
- 未定義だからといって新しい意味を作りません（[12章](#12-未定義不採用規約外コール)）。

### 1.8 改訂の手順

- **実装の不具合の修正**と、**規約そのものの変更**を区別します。
  - 不具合の修正：規約の文面どおりに動いていなかったものを直す。規約版は変えず、ビディングAIの版を上げる。
  - 規約の変更：コールの意味、保証、義務の発生・取消・履行の条件を変える。本書を改訂し、規約版とビディングAIの版を上げる。英語版と実戦ガイドは、本書に合わせて後から同期する（英語版や実戦ガイドを起点に意味を変えない）。
- 規約上の保証、CPUの通常目安（非保証）、義務を混ぜません。CPU内部の選択基準を、公開の保証として書きません。
- 版：規約版は規約の変更で上げます。ビディングAIの版は、不具合の修正と規約の変更で上げます。ゲームの版はゲームの側で管理します。現在の規約版は本書の冒頭、対象の実装の版は [13章](#13-付録acpu実装状況制約) に書きます。
- 判断理由・診断の形式と回帰テストの扱いは [13.6](#136-実装の管理) です。

## 2. 義務体系・切り札合意・義務の状態遷移

### 2.1 強制性の定義

| 状態 | 意味・終了 |
|---|---|
| `NF` | 新しい応答義務を作らない。ほかに義務がなければパートナーはPassできる |
| `INV` | ゲーム／スラムへの招待。新しいF1／GFを作らない。評価して辞退できる |
| `F1` | 指定されたパートナーの1回の有効な応答を求める。履行すると、その発生元の義務は消える |
| `GF` | 自陣がゲームに着くまで継続。スラムの義務ではない |
| `TO PLAY` | 自然な契約の選択。新しいF1／GFを作らない。別に残っている未履行の義務は別に判定する |
| 切り札合意 | 以後の契約探索で使う切り札を、公に合意した状態。GFとは別の状態 |
| 質問回答義務 | ガーバー／ブラックウッド／リフレインなどの指定された回答を求める。すでにゲームの高さでも、未回答なら残る |

### 2.2 義務の個別管理

- 義務は、**発生したコール・対象の席・履行の条件**ごとに管理します。
- 同じ応答が複数の義務を満たす場合も、義務ごとに判定します。
- 一つのF1の完了を理由に、別のF1・R02・GF・質問回答義務をまとめて解除しません。
- 取消は履行ではありません。取消のときは、発生元、取り消したコールの位置、理由を記録します（[11章](#11-競り合いdouble介入)）。

### 2.3 GFの履行と切り札合意

- GFは、**自然なゲーム契約の選択**、または**第9章の人工契約の最終採用**（[9.4](#94-人工回答へのpass終結とスラムの原則)）で履行します。
- 人工の3NT／4NTや、A回答の5♦などがゲーム以上の高さだというだけでは、GFは解除されません。
- GFだけから切り札を推定しません。自然な支持の情報と、明示的な切り札合意の状態を混同しません。

切り札合意が生じると規約に書かれている系列（本書の各章で【保証】として記載）：J07（[4.6](#46-再ビッドのジャンプj05j07)）、ジャコビー2NT（[8章](#8-ジャコビー2nt)）、D系列の3♠（2♠回答後）・4♣（[6.5](#65-d系列fsf回答後のsouth)）。D系列の2NT回答後の3♠はGFだが**切り札は合意しない**。介入後の限定自然支持（[11.5](#115-介入後の限定自然支持)）は、切り札合意を新たに自動で付けるものではありません。

### 2.4 義務の状態遷移

本表は、本書の規約が定める発生・履行・取消・維持の条件をまとめたものです。表にない組み合わせは【未定義】です。

| 義務 | 発生 | 履行 | 取消 | 介入（Double）での維持 | 残存・注意 |
|---|---|---|---|---|---|
| 自然なF1（R1、R01、REVERSE、初回の自然な新スート、SECOND など「1回はPassできない」義務） | そのコール | 指定されたパートナーの有効な応答（定義済みの自然なコール、または新しいF1・GF）。介入の後は、義務のある席の**数値ビッド**で履行（[11.4](#114-自然なf1への介入)） | 自然な初回応答の直後に相手が数値ビッドをしたとき、R1／R01がオープナーに作ったF1だけ（[11.4](#114-自然なf1への介入)） | 相手のDoubleでは維持（Passは義務違反として記録） | Redoubleは履行にならない。履行したコールに保証は追加しない |
| R02（応答者の再ビッド義務） | R01の後、ゲーム未満のとき | 限定的な選好・自己再提示・自然NTなど | R01の後に相手の数値ビッドがあったとき、まだ発生していないR02の予約を取り消す。後の任意の再ビッドで復活させない（[11.4](#114-自然なf1への介入)） | 相手のDoubleでは維持（Passは義務違反として記録。[11.4](#114-自然なf1への介入)） | 局所的なNFのラベルでR02を消さない（[5.2](#52-r02と通常の再ビッド)） |
| FSFのF1 | 人工FSF（A〜D） | Northの回答（各回答がFSFのF1を履行。新しいGFは作らない） | 未定義の後続・介入では補わない | （規約に個別の記載なし） | FSFはGFではない |
| GF | J04、J06、J07、ジャコビー2NT、D系列の指定コールなど | 自然なゲーム契約の選択、または人工契約の最終採用（[9.4](#94-人工回答へのpass終結とスラムの原則)） | 介入では取り消さない（[11.3](#113-人工の質問への介入)、[11.4](#114-自然なf1への介入)） | — | 人工3NT／4NTなどの高さだけでは解除しない。CPUはGF中にゲーム未満でPassしない（[2.6](#26-gf中の終局)） |
| 質問回答義務（ST01、ST03、AF01、特殊4Mへの4NT質問、ガーバー、プレーン・ブラックウッド） | 質問のコール | 指定された回答 | 回答の前に相手が数値ビッドをしたとき（[11.3](#113-人工の質問への介入)） | 相手のDoubleでは、質問と回答の義務を維持（[11.3](#113-人工の質問への介入)） | すでにゲームの高さでも、未回答なら残る |
| 質問者の最終契約の宣言（市ヶ谷リフレイン、特殊4Mへの4NT質問） | 回答（A・K・Q）が出たとき、質問者に | 次の質問、または質問ではない数値ビッド（最終契約） | 回答の後、質問者の次の手番までに相手が数値ビッドをしたとき（質問の系列が終わる。[11.3](#113-人工の質問への介入)） | 相手のDoubleでは維持（[11.3](#113-人工の質問への介入)） | 人工の回答へのPassは規約外の停止（[9.5](#95-特殊4mへの4nt質問)、[10.3](#103-質問と回答)） |
| INV・NF・TO PLAY | — | — | — | — | 新しい義務を作らない。すでにある義務は別に判定する |

### 2.5 複数の義務が同時にあるとき

- 例：リバースのF1の後に人工FSFを使い、その回答が出るまでの間は、リバースのF1の履行・FSFのF1・独立したR02・GF・質問回答義務を、それぞれ別に追跡します。
- 自然な初回応答の直後の介入による取消（[11.4](#114-自然なf1への介入)）は、そのR1／R01が作ったF1とR02の予約だけを取り消し、**すでに別に発生しているF1・GF・R02は維持**します。質問回答義務は [11.3](#113-人工の質問への介入) に従います。

### 2.6 GF中の終局

- GFが有効な間、CPUはゲーム未満の契約でPassして終わりません。
- 【CPU基準】通常の候補がないとき、CPUは、自然で定義済みのゲーム契約のうち、自分の枚数とパートナーの枚数（公開保証と通常目安）の合計が最も多いものを選んで義務を履行します。これはCPU内部の選択基準で、公開の意味や保証を増やしません。選んだコールの意味は、本書の規約どおり（支持・自己スート・NTのゲームなど）です。
- 相手の数値ビッドによる介入がある系列や、未定義・未対応の履歴の後には適用しません。
- 人間の合法なPassは制限しません（義務違反として記録するだけ）。

## 3. 全オープニングと強い自然2への応答

すべて**最初の数値ビッド**の文脈です。リフレイン専用の評価（[10.2](#102-cpu専用の評価)）を先に行い、採用しなければ通常の経路へ進みます。特殊な手を、HCPだけを理由に4♣へ送りません。

### 3.1 オープニング一覧

| ID・コール | 自然／人工・【保証】 | 【通常】・【CPU基準】・後続 |
|---|---|---|
| D01：`1NT` | 自然、**16–18 HCP（厳密）**、4333／4432／5枚マイナーの5332、5枚メジャーなし | 4441は不可。ステイマン、自然応答、第8・9章の質問へ |
| D02：`1♥ / 1♠` | 自然、提示メジャー **5+** | 【通常】13–21。16–18でも5枚メジャーは1NTより優先。長いメジャーから、同長のメジャーは♠（5–5を含む） |
| D02：`1♣ / 1♦` | 自然、提示マイナー **3+** | 5枚メジャーがなく、NTなどで始めない場合。長いマイナーから。3–3は♣、4–4以上の同長は♦。1♦を4+とはしない |
| `2NT` | 自然、**22–24** | 19–21は2NTで示さない（[3.2](#32-オープニングの原則)）。形は、5枚以上のスートのない最長4枚以下（4333／4432／4441）を運用の前提とする。形の公開保証の精密化は【未定義】（U04）。1NTの形の条件を転用しない |
| 強い自然2：`2♣ / 2♦ / 2♥ / 2♠` | 自然、初回応答に **F1**。**人工2♣ではない** | 【通常】22+。パートナーと契約を組み立てる。厳密な最低枚数と、25+で最長4枚の扱いは【未定義】（U04）。すべての強い手を人工2♣へ集約しない |
| PREEMPT3：`3♣ / 3♦ / 3♥ / 3♠` | 弱い3スート開始。[3.4](#34-弱い3スート開始) を参照 | — |
| D04：特殊4M（`4♥ / 4♠`） | 自然。パートナーの助けがなくてもゲームを見込める、長く強いメジャー（単独ゲーム級）。**弱いプリエンプトではない** | 枚数・HCP・自力トリック数の公開保証なし。直後のパートナーの4NTはAの総枚数の質問（[9.5](#95-特殊4mへの4nt質問)）。[3.6](#36-特殊4md04) |
| AF01：`4♣` | 人工、市ヶ谷リフレイン、Aの総枚数の質問 | [10章](#10-市ヶ谷リフレイン)。♣の長さを示さない |

### 3.2 オープニングの原則

- 19–21は、原則として自然な1スートのオープニングから強さを表現します。
- 【通常】13–21（1スート）や【通常】22+（強い2）を、独断で厳密なHCPの保証へ昇格させません。
- 2NTの帯域は22–24です。形の公開保証の精密化は U04 です。

### 3.3 通常のオープニングとプリエンプトの比較

- 長い有力なスートでの弱い3スートと、通常の1スートの情報交換を比べます。サイドのA／K、守備力、総合戦力が通常のオープニングに近ければ、1スートも候補になります。
- 12点で一律にプリエンプトにはしません。【通常】13点は厳密な下限ではなく、12点の通常のオープニングを禁止しません。新しい厳密なHCPの上限は作りません。

### 3.4 弱い3スート開始

- 【保証】最初の数値ビッドの `3♣`・`3♦`・`3♥`・`3♠` は自然・NF。宣言スートの**最低6枚**を公開保証します。HCPの上限・絵札の配置は保証しません。
- 【通常】標準は7枚以上、CPUの通常推定は7枚中心。
- 5枚以下は規約不適合ですが、人間の合法なコールは許容します。応答・再ビッド・オーバーコールへ流用しません。
- 【CPU基準】CPUの開始条件は12HCP以下。7枚の場合の品質条件（CPU内部）に加え、ちょうど6枚なら AKQ、または AKQJ の3枚以上と10か9を必要とします。これはCPUの基準で、公開の絵札の保証ではありません。連続性、欠けたA／K、サイドの絵札、別の有力なスート、6枚のリスクを評価し、通常のオープニング・Pass・特殊なオープニングと比べます。
- 応答側は、公開の最低6枚と【通常】7枚中心を分けます。支持が2／3／4枚なら、最低fitは8／9／10、通常推定fitは9／10／11。自分の戦力・切り札の品質などで、Passと自然なゲームへの引き上げを比べます。NFは停止の許可であって、停止の強制でもゲームの強制でもありません。詳細が未定義の応答へ、新しいF1／GF・人工の意味を追加しません。

### 3.5 強い自然2への応答（F02）

- 弱い3同スート（例：`2♥–3♥`）は、**支持枚数の保証がない**特殊な弱い応答です。初回のF1を履行し、新しいGFを作りません。オープナーは自力トリックと公開情報から、Passか自然な継続を選びます。22+だからといってゲームを強制しません。
- 肯定的な新スートは、新たなF1です。
- 【通常】目安：強い2Mへ、通常4+・支持3+なら4Mを検討、通常10+なら自然な新スート、弱ければ3M。強い2mへは、有力な5枚メジャー、適切な3NT、弱い3mを比べる。これらのCPU目安を、回答の厳密なHCP・支持の保証へ転用しません。
- 未定義の詳細は U04 です。

### 3.6 特殊4M（D04）

- 最初の数値ビッドとしての `4♥`／`4♠`。自然なオープニングです。
- パートナーの助けがなくてもゲームを見込める、長く強いメジャーを示します（単独ゲーム級）。**弱いプリエンプトではありません。**
- 【保証】は設けません：厳密なスートの枚数、HCP、自力トリック数のいずれも公開保証ではありません。
- リフレイン（[10章](#10-市ヶ谷リフレイン)）の評価を先に行い、比べる原則は同じです。
- 4Mのオープニングで切り札合意は生じません。席や先行のPassについての保証はありません。
- 応答：直後のパートナーの4NTは、Aの総枚数の人工の質問です（[9.5](#95-特殊4mへの4nt質問)）。それ以外の応答・継続は【未定義】（U04）。
- 【CPU基準】CPUがこのオープニングを選ぶ条件と、CPUの応答者の選び方は [13.4](#134-本書のcpu基準の一覧) を参照してください。

## 4. 初回応答・支持・再ビッド・自然NF停止

### 4A 初回応答

以下は原則として、非競り合い・未パスの初回応答です。

- 初回の自然な新スートは、オープナーに F1 を作ります。
- 人間の合法なPassを禁止するものではありません。

### 4.1 初回応答の一覧

| ID・完全な文脈の型 | 【保証】・自然／人工・義務 | 【通常】・応答／未定義の境界 |
|---|---|---|
| J01：`1M–2M` | 自然、M **3+**、NF | 通常6–10。最小ならPass、追加戦力なら招待・ゲーム。招待の新スートの詳細は【未定義】（U07） |

| J03：`1M–4M` | 自然、M **5+** とサイドのシングルトン／ボイド、TO PLAY | 通常0–9の弱い分布型。通常はPass、特別な材料があれば継続 |

- J01／J02 の通常10点の重なりは裁量で、意味の二重定義ではありません。
- 単純支持 J01／M01 は、パストハンドにも適用します。他の規約をパストハンドへ自動で広げません。

### 4.2 弱い手の初回選択

1♣に対する次の組み合わせを、CPUの明示的な優先条件として保持します。

| 弱い手の組み合わせ | 原則の初回選択 |
|---|---|
| ♠5枚・♦4枚 | 1♠ |
| ♥5枚以上・♠4枚 | 1♥（♥6枚以上の6形状も同じ） |
| ♦5枚・♥4枚 | 1♦ |

- 【通常】通常6〜9程度の弱い応答を想定します。弱さの厳密な境界や、表にない二色形の全優先順位は追加しません。
- 【CPU基準】これらはCPUの選択方針で、**選ばれなかったスートの不在の保証ではありません**。6+なら原則として何らかの初回応答を比べますが、【未定義】の1m–1NTを救済として追加しません。人間が合法な別のコールを選べることと区別します。

### 4.3 ゲーム・招待・支持

- 支持できることと、すぐにゲームを宣言すべきことは別です。低い支持・招待・ゲーム・Passの契約品質を比べます。パートナーがパストハンドなら、公開履歴に基づく通常戦力を保守的に更新します。
- 1レベルのメジャーの提示の4枚の保証・暫定推定を、5枚に格上げしません。自分の3枚とパートナーの4枚では、8枚fitは確定しません。
- HCPに加え、長さ、切り札の品質、短さ、Aなどのコントロールを評価します。ただし、短さで孤立した絵札が失った価値を二重に加算せず、同じ長さ・勝ち札を複数の加点で重複して数えません。13点・6枚・シングルトン・3Aも比較の材料で、ゲームの義務ではありません。
- 競り合い・パストハンドの【未定義】の支持に、新しい公開の枚数・INV／GFを付けません。自然な暫定比較は CPU_ESTIMATE として記録します。[11.5](#115-介入後の限定自然支持) の限定4枚支持を3枚へ変更しません。

### 4.4 マイナーへの応答

- 1♣に対して、自分に♦5枚と♣の支持がある場合、1♦の低コストな情報価値と、2♣の支持の価値を比べます。2♣を禁止しません。
- 1♦の未確定の最低枚数を、CPUの5枚の条件で保証にしません。パストハンドの未定義の自然応答は、未定義のままです。
- 4-4-2-3 の通常の1♣と、M01の3枚支持を維持します。

- パートナーの2NTを受け、公開の通常戦力と自分の手札で、Pass／3NTを比べます。人間が14点で2NTを宣言しても、CPUはその隠れた14点を入力にしません。NFはPassの許可で、Passの評価の加点ではありません。
- D系列の直接2NTは弱いNF、FSFの回答の2NTは厳密なストッパー付きの回答、ジャコビー2NTは人工GFで、本節のINVを流用しません。

## 6. 人工FSF A〜D・確定後続

### 6.1 前提と開始

前提：相手が全Pass、初回の応答者が未パス、規約に合う自然な開始・第二スート。次の**完全な4系列だけ**を人工化します。

| 系列 | 開始する完全な系列 | 公開の意味 |
|---|---|---|
| A | `1♦–1♥–1♠–2♣` | 人工2♣、♣の枚数の保証なし、Northに F1 |
| B | `1♣–1♥–1♠–2♦` | 人工2♦、♦の枚数の保証なし、Northに F1 |
| C | `1♣–1♦–1♥–1♠` | 人工1♠、♠の枚数の保証なし、Northに F1 |
| D | `1♣–1♠–2♦–2♥` | 人工2♥、♥の枚数の保証なし、Northに F1。Southのリバースの F1 を履行 |

- 【通常】通常10HCP以上は目安で、厳密な下限ではありません。9以下でも形・情報の価値による例外を許容しますが、6〜9程度では自然な停止を原則として優先します。1レベルのCだけに追加の条件を作りません。
- **FSFはGFではありません。** A〜Cでは、通常、FSFの直前にSouthのF1は残っていません。存在しない義務を作りません。

### 6.2 Northの回答

各行の文脈は、上の完全な系列の直後です。回答は自然な契約の候補で、人工FSFへの回答だからといって全部を人工にはしません。

| 系列 | 支持（最優先） | 元のスート | NT |
|---|---|---|---|
| A | `2♥`：♥3+ | `2♦`：♦4+ | `2NT`：♣A または ♣KQ を厳密保証 |
| B | `2♥`：♥3+ | `3♣`：♣4+ | `2NT`：♦A または ♦KQ を厳密保証 |
| C | `2♦`：♦3+ | `2♣`：♣3+ | `2NT`：♠A または ♠KQ を厳密保証 |
| D | `2♠`：♠3〜4 | `3♣`：♣5+ | `2NT`：♥A または ♥KQ を厳密保証 |

- 支持できるなら支持を最優先します。支持できなければ、元のスートとNTを比べます。
- NTには、上の表の厳密な札の条件と、NT適性が必要です。【通常】15+ は厳密な下限ではなく、Dの既知のリバースの戦力を二重に加点しません。バランス型に限りません。Aなら1枚でもあるので、第四スートの2+までは保証しません。ストッパーがあってもNTを強制せず、元のスートの回答からストッパーの不在を推論しません。
- 各回答はFSFのF1を履行し、それだけで新しいGFを作りません。別の義務がなければ、SouthはPassできます。第一・第二スートの既知の保証を引き継ぎます。Cの2♣（3+）とDの3♣（5+）を統一しません。A／Bの開始の全部の手で、元のマイナーの4+を保証するのではなく、該当する回答をしたときの保証です。
- 支持最優先を厳格に守る文脈では、Dの2NT／3♣は♠2枚以下と推論できます。人間の逸脱の実際の手札を見て修復しません。第二メジャーの再提示は標準の回答に含めません（5+の保証もしません）。Aの3♣に人工の追加の意味を割り当てません。

### 6.3 A〜Cの確定後続と境界

`1♦–1♥–1♠–2♣–2♥–?`：

| South | 意味・【保証】 | 義務／合意・後続 |
|---|---|---|
| Pass | 2♥を採用 | 独立した義務がない場合 |
| `3♥` | 自然、♥5+、最低8枚fit、INV | GFではない。NorthはPass／4♥を評価 |
| `4♥` | 自然 TO PLAY。初回の♥4+は継承 | 7枚fitも排除しない。追加の5枚の保証なし |

- Aの3♥の招待を受けたNorthは、【通常】13〜14で辞退寄り、15で比較、16〜17で積極的に受諾、18+でゲームを強く検討。形の例外を許し、HCPの固定判定や二重加点をしません。
- A〜CのNT回答の後は、Pass／3NT／自然なスートの継続を比べます。2NT回答だけではGFになりません。元のスートの回答の後は、支持・自己再提示・NT・安全な停止を比べる方針です。
- **Cの確定した1系列**：非競り合い・未パスの応答者の `1♣–1♦–1♥–1♠(人工FSF-C)–2♣–4♥` は**自然 TO PLAY**。新しいHCP・支持枚数の保証・GF・切り札合意は付けません。初手・第二スートの保証は継承します。FSFの回答義務は2♣で履行済みで、独立した義務は保持します。3♥の招待や、他のB／Cの後続へ転用しません。CPUの比較は [6.6](#66-fsfの選択と3nt4mの比較)。
- **Bの2♥の後の3♥のINV／GF、Cの個別の再提示の最低枚数・新しいGFなど、上記以外の系列固有の詳細は【未定義】（U02）。** AのINVやDのGFを移植しません。初回の1♦の公開の最低枚数が未確定なので、Cの支持2♦だけで8枚fitと断定しません。

### 6.4 D系列：リバース直後のSouth

`1♣–1♠–2♦` は、Northの♣5+、♦4+、♣>♦、【通常】17–21 のリバースです。Southは初回に♠4+、Southにリバースの F1 があります。以下の系列は全部この前置きを含みます。

| South | 自然／人工・【保証】 | 【通常】・義務 |
|---|---|---|
| `2♠` | 自然、♠5+ | 弱い停止志向、NF |
| `2♥` | 人工FSF、♥の長さなし | [6.1](#61-前提と開始)、Northへ新しいF1 |
| `2NT` | 自然。追加のHCP・形・♥A／KQの厳密な保証なし | NT適性は必須。通常6〜9、弱い停止志向、NF。ゲームの招待ではない。バランス型に限らない |
| `3♣` | 自然、♣2+ | 消極的な選好、NF。最低7枚fit |
| `3♦` | 自然、♦3+ | 消極的な選好、NF。最低7枚fit |

- 有効な応答でリバースのF1を履行します。NFの経路なら、別の義務がなければNorthはPassできます。
- 2♠はNorthの支持を保証しません。♣／♦の選好は、積極的な8枚fitの保証ではありません。弱い♥5+♠4は [4.2](#42-弱い手の初回選択) で初回1♥を優先しますが、人間の合法な1♠を禁止しません。

**直接2NTを受けたNorth**：`1♣–1♠–2♦–2NT–?` では、Passが標準の候補です。3NTは自然 TO PLAY、新しいGFなし。9トリックの成立見込みを重視し、19HCP前後から積極的に比べますが、固定の閾値にしません。Southの通常6〜9を推定に使い、招待とも♥のストッパーの保証とも解釈しません。自分の手札と公開履歴だけで評価します。**Northの3♣など、他の継続は【未定義】（U05）。**

### 6.5 D系列：FSF回答後のSouth

| 完全な系列の前置き | South | 【保証】・自然性 | 義務・切り札合意・後続 |
|---|---|---|---|
| `1♣–1♠–2♦–2♥–2♠` | Pass | 2♠を採用 | 別の義務がなければ可 |
| 同上 | `3♠` | 自然、♠5+、最低8枚fit | **GF、♠合意**。Northの4♠はゲームの選択、4NTはブラックウッド |
| 同上 | `3NT` | 自然 TO PLAY | 新しいGFなし |
| 同上 | `4♠` | 自然、♠4+、TO PLAY | 7枚fitも許容 |
| `1♣–1♠–2♦–2♥–2NT` | Pass | 2NTを採用 | 別の義務がなければ可 |
| 同上 | `3♠` | 自然、♠6+ | **GF、切り札は未合意**。Northが♠0〜1なら通常3NT、2枚なら3NT／4♠を比較 |
| 同上 | `3NT` | 自然 TO PLAY | 新しいGFなし |
| `1♣–1♠–2♦–2♥–3♣` | Pass | 3♣を採用 | 別の義務がなければ可 |
| 同上 | `3NT` | 自然 TO PLAY | Southの♥A／KQは原則【CPU基準】。公開保証ではない |
| 同上 | `4♠` | 自然、♠6+、TO PLAY | Northは♠0〜2なので8枚fitを保証しない |
| 同上 | `4♣` | 自然、♣3+、最低8枚fit | **GF、♣合意**。スラム専用ではない |
| 同上 | `5♣` | 自然 TO PLAY | ♣のfitと11トリックを評価。3NTが危険だというだけでは選ばない |

- Northの2♠は3〜4枚なので、最初のSouthの♠4枚と合わせて7枚fitはあります。3♠GFでも、2NT回答の後の系列では♠合意を発生させません。表以外の追加の継続は【未定義】です。

**自然4♣GFの後**：`1♣–1♠–2♦–2♥–3♣–4♣–?` で、Northの5♣は自然 TO PLAYでGFを履行します。Northの4NTは、♣合意の後のプレーン・ブラックウッド（[9.2](#92-プレーンブラックウッド)）。4♣での規約に適合するPassは不可。キュービッドを追加しません。質問回答の義務とGFを別に保持します。

### 6.6 FSFの選択と3NT／4Mの比較

- 【CPU基準】Cの確定した1系列（[6.3](#63-acの確定後続と境界)、`1♣–1♦–1♥–1♠–2♣–4♥`）について、CPUは、自分の手札と公開の最低枚数で♥8枚以上なら、4♥を3NT・Passと比べます（4♥は必須ではない）。3♥の招待や、他のB／Cの後続へ転用しません。
- 【CPU基準】FSFの選択では、既知のメジャー8枚fitがある場合に追加の情報の限界的な価値を低く評価します。確認したいスートがあるだけで一律に最大の加点をしません。HCPの境界での急な基礎点の差を緩めます。スラムの成功見込みや探索の価値を、根拠なく加点しません。係数はCPU内部の基準です。
- 【CPU基準】3NTと4Mが実力伯仲なら、小さなメジャーの選好を許容します。明確なNTの優位を覆さず、同じ候補へ二重に補正しません。

## 7. NT体系・ステイマン

1NTは [3.1](#31-オープニング一覧) の保証（D01）です。ステイマンは任意で使います。以下の指定の系列以外は、2NTオープニングへのステイマン／トランスファーへ広げません。

### 7.1 1NTへの直接応答

| 完全な文脈 | 意味・【保証】 | 義務／継続 |
|---|---|---|
| `1NT–2♣`（ST01） | ステイマン（[7.2](#72-ステイマン)） | F1 |
| `1NT–2♥ / 2♠`（直接） | 自然、提示 **5+**、弱いパートスコア志向、NF | トランスファーではない。ゲーム志向の長いメジャーは、原則ステイマン経由 |
| `1NT–2♦`（直接） | **【未定義】** | トランスファーなどに置き換えない |
| `1NT–2NT` | 自然 INV | 【通常】6–8 |
| `1NT–3NT` | 自然 TO PLAY | 【通常】9+ |

- 【通常】直接の弱い2Mは通常0–7。いずれもHCPの保証ではありません。1NTへの直接の2Mの5+に「必ず6枚」を追加しません。
- 1NTへの直接4♣はガーバー、直接4NTは量的4NTです（[9章](#9-ガーバーブラックウッド量的4nt)）。

### 7.2 ステイマン

1. **開始条件**：`1NT–2♣`（ST01）。任意使用。
2. **質問の意味**：人工。4枚メジャーの有無の質問。♣・メジャーの枚数の保証なし。F1（回答義務）。【CPU基準】CPUは、通常8+で、4枚以上のメジャー／長いメジャーのゲーム探索で使う目安。質問そのもののHCPの厳密な保証はない。
3. **回答コールと保証**：

| 系列 | 意味・【保証】 | 義務 |
|---|---|---|
| `1NT–2♣–2♦` | 人工、両メジャーとも3枚以下 | 初回のF1を履行、GFなし |
| `1NT–2♣–2♥` | 人工、♥4枚。**両メジャー4枚なら♥優先** | ♠4枚を否定しない。初回のF1を履行 |
| `1NT–2♣–2♠` | 人工、♠4枚・♥3枚以下 | 初回のF1を履行 |

4. **後続の質問・回答**：

| 系列 | 意味・【保証】 | 義務／継続 |
|---|---|---|
| `1NT–2♣–2♥–2♠` | 人工。応答者の♠4+、オープナーの♠4枚の有無を質問 | F1。オープナーは♠4枚なら `3♠`（自然な支持、NF）、なければ `2NT`（人工、♠3枚以下、NF） |
| `1NT–2♣–2♦–2♥ / 2♠` | 自然、提示メジャー **5+**、招待以上 | F1。オープナーは3枚支持なら `3M`（自然、NF）、2枚以下なら `2NT`（人工、NF） |
| `1NT–2♣–2♠–3♥` | 自然、♥ **5+**、招待以上のゲーム志向 | F1。オープナーは♥3枚なら `4♥`（自然）、2枚以下なら `3NT`（自然） |

5. **停止・契約選択**：【CPU基準】ステイマンの後の長いメジャーの継続は通常8+。回答の2Mへの自然な3同Mの招待は4枚支持、通常8点。全部のステイマンの系列をGFにしません。質問への回答の後も、別の義務があれば残ります。
6. **介入時の扱い**：回答の前に相手が数値ビッドをすると、回答義務は取り消されます（`1NT–(Pass)–2♣–(2♠)` を含む。[11.3](#113-人工の質問への介入)）。相手のDoubleでは回答義務は残ります（[11.3](#113-人工の質問への介入)）。
7. **未定義の境界**：直接2♦は【未定義】。ステイマンの後のガーバーへの接続・競り合いなどは【未定義】。2NTオープニングへのステイマンは適用しません。

ST03：規約本文では、ステイマンの後続の人工の質問を指す名前としてだけ使われ、定義の本文はありません。実装では、上の後続（`2♥–2♠`、`2♦–2M`、`2♠–3♥`）に内部ID ST03-S／ST03-5M／ST03-5H を使っています（[14.4](#144-名前だけのid)）。

## 8. ジャコビー2NT

1. **開始条件**：自然な1♥／1♠への、未パス・非競り合いの直接2NT（D09）。
2. **質問の意味**：人工、M **4+（厳密）**、GF、そのMで切り札合意。NTの提案ではない。【通常】13HCPを基本案とするが、下限の保証なし。fit・短さ・絵札・トリック源を評価し、ゲームだけでなくスラムの探索の入口にするが、スラムを約束しない。強い3枚支持は対象外で、自然な新スートか、適合するF01へ。
3. **回答コールと保証（オープナーの人工の短さの回答）**：

| 合意 | `3♣` | `3♦` | `3♥` | `3♠` | `3NT` |
|---|---|---|---|---|---|
| ♠ | ♣0–1 | ♦0–1 | ♥0–1 | サイドの短さなし | 未割当 |
| ♥ | ♣0–1 | ♦0–1 | 未割当 | ♠0–1 | サイドの短さなし |

- 短さなしは、全部のサイドが2+。複数の短さがあれば該当のどれでもよく、【CPU基準】CPUは低いスートの順。0と1を区別しない。人工の3NTは契約の提案ではなく、GFを解除しない。

4. **後続の質問・回答（応答者のAの所在の報告）**：直前の回答の次の数値ビッドから、Aなし／♣A／♦A／♥A／♠A を割り当てます。

| 直前 | Aなし | ♣A | ♦A | ♥A | ♠A |
|---|---|---|---|---|---|
| `3♣` | `3♦` | `3♥` | `3♠` | `3NT` | `4♣` |
| `3♦` | `3♥` | `3♠` | `3NT` | `4♣` | `4♦` |
| `3♥` | `3♠` | `3NT` | `4♣` | `4♦` | `4♥` |
| `3♠` | `3NT` | `4♣` | `4♦` | `4♥` | `4♠` |
| `3NT` | `4♣` | `4♦` | `4♥` | `4♠` | `4NT` |

- 報告は最大1枚。Aなしは総数0。報告しなかったAの不在は保証しません。複数のAがあるときの♣♦♥♠の優先は【CPU基準】。短さのスートのAも対象。Kはこの段階で報告しません。

5. **停止・契約選択**：
   - `1♥–2NT–3NT–4NT` は♠Aの報告で、ブラックウッドではありません。同じ4NTを重ねられないので、次の5♥／6♥／7♥などから合法に選びます。この停止の超過を許容します。
   - 報告が合意した4Mそのものなら、[9.4](#94-人工回答へのpass終結とスラムの原則) でPassの採用ができます。それ以外はGFを守り、新しい合法な契約や、使えるブラックウッドを選びます。全部のAの所在が判明したとは扱いません。
6. **介入時の扱い**：【未定義】（人工の質問への介入の規定（[11.3](#113-人工の質問への介入)）の対象に、ジャコビー2NTは含まれません）。
7. **未定義の境界（U09）**：0／1の追加の確認、普通のGFの支持とスラム志向の厳密な数値の区分、適切な自然スートもバランス型でもない強い3枚支持の手の全経路は【未定義】。本章の短さの表・1枚のA報告・F01は変えず、新しい人工の応答は追加しません。

【CPU未対応】CPUはジャコビー2NTを開始せず、上の回答・後続も実装していません（[13章](#13-付録acpu実装状況制約)）。

## 9. ガーバー・ブラックウッド・量的4NT

### 9.1 ガーバー

1. **開始条件**：自然な1NT／2NT**オープニングへの直接の4♣**。FSFの回答の2NTの直後だからといって、自動でガーバーにはしません。
2. **質問の意味**：人工、Aの質問、F1（回答義務）。
3. **回答コールと保証**：

| 質問 | 0または4 | 1 | 2 | 3 |
|---|---|---|---|---|
| `4♣`：A | `4♦` | `4♥` | `4♠` | `4NT` |
| A回答の後、質問者の `5♣`：K | `5♦` | `5♥` | `5♠` | `5NT` |

4. **後続**：K質問は、原則として4Aを確認し、グランドスラムを検討するとき。**Q質問は設けません【不採用】。**
5. **停止・契約選択**：5♣以外の自然な最終契約の提示は TO PLAY。別の義務がなければ、回答者はPass。
6. **介入時の扱い**：[11.3](#113-人工の質問への介入)。
7. **未定義の境界**：ステイマンの後のガーバーへの接続は【未定義】（[7.2](#72-ステイマン)）。D系列の自然な4♣はガーバーではありません。

### 9.2 プレーン・ブラックウッド

1. **開始条件**：明示された人工の報告・質問の系列の例外を除き、**切り札合意の後の4NT**。
2. **質問の意味**：人工、Aの総枚数の質問。回答義務が独立して発生します。
3. **回答コールと保証**：

| 質問 | 0または4 | 1 | 2 | 3 |
|---|---|---|---|---|
| `4NT`：A | `5♣` | `5♦` | `5♥` | `5♠` |
| A回答の後、質問者の `5NT`：K | `6♣` | `6♦` | `6♥` | `6♠` |

- Aには、切り札のKもボイドも数えません。ジャコビー2NTですでに報告したAも総数に含め、二重に数えません。Kは切り札のKを含む総数。
- 0と4は可能な集合として保持し、自分の手札・公開情報で一意になる場合だけ解消します。隠れた他の席の手札を参照しません。
- **RKCBと専用のQ質問は【不採用】。**

4. **後続（5NT）**：5NTは、その質問者によるK質問の文脈に限ります。原則として4Aを確認した後、少なくとも小スラムを戦えるという判断で使います。ボイド・トリック源による合理的なAの不足の例外を許容します。別の文脈の5NTへ自動で適用しません。
5. **停止・契約選択**：

| 合意した切り札 | A回答の後の停止の制約 |
|---|---|
| ♠ | 5♣／5♦／5♥ から 5♠ にできる。5♠の回答はPassで採用できる |
| ♥ | 5♣／5♦ から 5♥ にできる。5♥の回答はPassで採用できる。5♠ から 5♥ へは戻れない |
| ♣（D系列を含む） | 5♣の回答だけ、Passで採用して5♣で停止。5♦／5♥／5♠ からは♣の契約は最低6♣ |

- 同じ契約の再提示は禁止です。Kの回答も6♣／6♦／6♥／6♠の実際のレベルに従い、例えば♥合意で6♠から6♥へは戻れません。回答が予定の停止を超えるリスクを許容し、新しい停止の例外を作りません。5NTを逃げ道にしません。
6. **介入時の扱い**：[11.3](#113-人工の質問への介入)。
7. **未定義の境界**：高度なスラム探索は扱いません。キュービッドは【不採用】です（[12.4](#124-不採用)）。

### 9.3 量的4NT

- 自然なNTの強さが分かっていて、切り札を探す必要がなく、**切り札が未合意の4NT**は、NFの6NTへの招待です。人工の質問・ジャコビーの報告が優先します。A／KやGFは保証しません。
- 【通常】1NT（16–18）への直接4NT：応答者は通常15–16のバランス型。オープナーは16で辞退、18で受諾、17はトリック源などで比べる。
- 【通常】2NT（22–24）への直接4NT：応答者は通常9–10のバランス型。オープナーは22で辞退、24で受諾、23は比べる。
- 数値は目安で、厳密な保証はありません。1NTへの13–14は通常3NT、特別な実働戦力があれば探索の余地。指定外の詳細を、質問と回答へ読み替えません。

【CPU未対応】CPUは量的4NTの開始・回答に対応していません（[13章](#13-付録acpu実装状況制約)）。

### 9.4 人工回答へのPass終結とスラムの原則

- 回答が済んだ後、人工の回答の契約が**合意した切り札のゲーム以上と一致**し、他に未履行の義務がなければ、質問者／オープナーはPassで最終採用できます。GFはその採用で到達の条件を満たすので、循環的にPassを禁止しません。
- ゲーム未満のGF、未回答の質問、別のF1は解除しません。♣合意の5♦の回答へのPassを、この規則で認めません（人間の競技上合法なPassとは別）。
- Aの枚数・所在、短さ、切り札、K、トリック源を評価します。4Aでも成功の保証はなく、Aが足りなくても短さなどで探索できます。極端な分布や回答の停止の超過を許容し、回答の高さそのものを強さと誤認しません。**キュービッドは【不採用】（未採用）。**
- 本節は、合意した切り札がある場合の規則です。切り札合意のない特殊4Mへの4NT質問（[9.5](#95-特殊4mへの4nt質問)）には適用しません。

### 9.5 特殊4Mへの4NT質問

1. **開始条件**：特殊4M（`4♥`／`4♠`、[3.6](#36-特殊4md04)）のオープニングの直後に、相手の介入（Pass以外のコール）がなく、パートナーが最初のビッドとして宣言する `4NT`。
2. **質問の意味**：人工。オープナーが持つAの総枚数の質問。F1（回答義務）。プレーン・ブラックウッド（切り札合意の後）、量的4NT（自然NTの文脈）、ジャコビー2NTのAの報告の4NTとは、文脈で区別します（[1.5](#15-解釈の優先順位)）。
3. **回答コールと保証**：

| 系列 | 回答 | Aの総枚数 |
|---|---|---|
| `4M–4NT` | `5♣` | 0または4 |
| 同上 | `5♦` | 1 |
| 同上 | `5♥` | 2 |
| 同上 | `5♠` | 3 |

4. **後続の質問・回答**：質問者がA回答の**直上**をビッドするとKの総枚数の質問、K回答の直上ならQの総枚数の質問です。K・Qの回答も、質問の次の数値ビッドから同じ4ステップ（0／4・1・2・3）。Q回答の後に追加の質問はありません。
   - 回答の直上は常に次の質問で、自然な停止ではありません。例：`4♥–4NT–5♦–5♥` の5♥はKの質問です。
5. **停止・契約選択**：
   - 質問者が、質問ではない合法な数値ビッドをすると、自然な最終契約（TO PLAY）です。
   - 質問者は、回答の後に最終契約を宣言します。**人工の回答へのPassで契約を採用することは、規約に適合した停止ではありません。** 人間の合法なPassは受け付け、規約外の停止として記録します。CPUは人工の回答へのPassで止まりません。[9.4](#94-人工回答へのpass終結とスラムの原則) のPassでの採用は、切り札合意がないので適用しません。
   - 回答で得るのは総枚数で、所在ではありません。0と4は、自分の手札と公開情報から一意になる場合だけ区別できます。
6. **介入時の扱い**：質問・次の質問の回答の前に相手が数値ビッドをすると、回答義務は取り消されます。相手のDoubleでは、質問と回答の義務・意味を維持します。回答の後、質問者の次の手番までに相手が数値ビッドをすると、質問の系列は終わり、質問者の最終契約の宣言の義務は解除されます（その後の意味は【未定義】）。相手のDoubleの後も、質問者は最終契約を宣言します（[11.3](#113-人工の質問への介入)）。4NTの前に相手が介入した場合、その4NTは本節の質問ではありません（【未定義】）。
7. **未定義の境界**：4Mへの4NT以外の応答・継続は【未定義】（U04）。

【CPU基準】CPUの質問者は、自分のA（またはK）の枚数と回答から、合計が3以上なら6レベル、そうでなければ5レベルで、**オープナーの4Mのスート**の最終契約を選びます（合法でない、または回答の直上になる場合はレベルを上げます）。合計が4枚と確認できれば、次の質問をします。

## 10. 市ヶ谷リフレイン

### 10.1 位置づけ

- 正式名 **Ichigaya Refrain（市ヶ谷リフレイン）**、規約ID AF01。発動の愛称は **Ichigaya Fever**、ログの表記は `ICHIGAYA FEVER`。
- 4♣オープニングは、オープナーが戦うスート／NTと目標の契約をすでに想定し、**最後の不足情報を確認する人工の開始**です。パートナーの分布・fitを見て契約を組み立てる強い自然2（[3.5](#35-強い自然2への応答f02)）とは役割が違います。

### 10.2 CPU専用の評価

この節の内容は、すべて【CPU基準】で、公開保証ではありません。

- 通常のオープニングより先に、`HCP≥21 OR 最長≥7 OR 自力トリックの見込み≥7` なら専用の評価へ入ります。入口を通っても採用ではありません。
- 自力トリックは、実際のカードからHCPと独立に評価します。AKQJ109＋別のAは入口の7トリック。AKQ／AKQ／Kx のKxを確定トリックにしません。
- 最終評価は、期待トリック、連続した上位札、長さ、条件付きのK／Q、短さ、通常の分布、欠けた札、エントリー、主導権、質問の価値の加減点の台帳です。勝ち札と形を二重に計上しません。パートナーを含む未知の3人を考慮し、必要な札をパートナーが持つ前提にしません。やや楽観的な初期係数と、調整可能な閾値を使います。不利な分布が50%未満程度なら許容する方針は、厳密な確率の保証ではありません。
- 採用の閾値は調整可能なCPU内部の値で、規約の値ではありません。
- 入口のORと、総枚数の A→K→Q を維持します。8枚AKQ・複数のAなどは必須条件ではありません。自己完結性と、総枚数の回答で目標の契約の評価が変わる価値を台帳にし、通常の開始・特殊4M・直接の最終契約と比べます。係数は調整可能なCPU内部の値です。未知の所在を質問の価値として満額で加算しません。回答で一意に推論できる場合だけ所在が確定します。自分の13枚に同じスートが揃っていれば、質問は不要で、直接7スートを比べられます。開始の前に、回答のステップと次の質問を除いた合法な停止の契約を確かめ、毎回4♣へ誘導しません。

### 10.3 質問と回答

1. **開始条件**：最初の数値ビッドとしての `4♣`（AF01）。♣の長さを示さない。
2. **質問の意味**：人工、Aの総枚数の質問。回答義務。
3. **回答コールと保証**：質問の次の数値ビッドから4ステップで、0／4・1・2・3。

| 系列 | Aの総枚数 |
|---|---|
| `4♣–4♦` | 0または4 |
| `4♣–4♥` | 1 |
| `4♣–4♠` | 2 |
| `4♣–4NT` | 3 |

4. **後続の質問・回答**：A回答の直上を質問者がビッドしたら**K質問**、K回答の直上なら**Q質問**。KとQの回答も同じ4ステップです。Q回答の後に追加の質問はなく、その直上も最終契約の候補になります。
5. **停止・契約選択**：
   - A→K→Q を全部質問する義務はありません。A／K回答の直上以外の合法な最終契約を提示して止められます。例：`4♣–4♦–4♥` の4♥はK質問で、4♥のサインオフではありません。
   - 自分だけが想定した切り札を公の合意として扱い、人工の回答にPassして契約を採用してはいけません。人間の合法なPassは受け付け、規約外の停止として記録します（[12.1](#121-人間の規約外コール)）。CPUは人工の回答へのPassで止まりません。
   - 質問で得るのは **A／K／Qの総枚数**で、所在ではありません。自分のA3＋パートナーのA1なら欠けたAの所在は一意、自分のA2＋パートナーのA1ではどちらか不明。質問前の情報の価値を回答後まで残さず、論理的に確定した条件だけを差分で更新します。
   - 質問の前・次の質問の前に、合法な停止の計画を確かめます。普通の回答で合理的な停止がなくなる場合は、開始の評価を下げます。まれな高い回答による超過は許容し、複雑な例外を新設しません。入口を通った後は、不採用も含めて、入口の理由、基礎のトリック、形、質問の期待、リスク、最終値、閾値、採否の理由を記録します。
6. **介入時の扱い**（[11.3](#113-人工の質問への介入)）：相手のDoubleの後も、意味と回答義務、回答の後の質問者の契約選択は変わりません。回答の前の相手の数値ビッド（例 `4♣–(4♥)`）では回答義務を取り消します。
   - **回答の後の相手の数値ビッド**：A・K・Qの人工の回答の後、質問者の次の手番までに相手が数値ビッドで介入したら、その質問の系列は終わり、その系列に由来する質問者の最終契約の宣言の義務は解除します。回答の後の相手のDoubleでは、系列と宣言の義務を維持します。別に発生しているF1・GFなどの独立した義務は取り消しません。介入の後の自陣のコールに、新しい意味や保証を与えません（未定義の競り合い）。人間の合法なコールは、引き続きすべて選べます。
7. **未定義の境界**：回答後の高度な再評価は規約で詳しく定めていません（原則は上の5）。

## 11. 競り合い・Double・介入

### 11.1 適用範囲と共通原則

- 本章は、相手の介入のうち、以下の節で定める**完全な文脈だけ**を扱います。一般の競り合い（オーバーコール、テイクアウト）、低いレベルのDouble、Redoubleは、本章で定めたもの以外は【未定義】です。
- 介入の規定がない部分（非競り合いのR1／R01／R02、ステイマン、FSF、ジャコビー、ガーバー、ブラックウッド、リフレイン）は、各章の規約のとおりです。本章はそれを変えません。
- 人間の合法な規約外のコールは許容します。
- 取消は履行ではありません。取消のときは、発生元、取り消したコールの位置、理由を記録します（記録の書式は [13.3](#133-フォールバックの基本原則)）。
- 取消と、候補の不足・評価によるPassは、別の診断です。
- 隠れたカードや相手のCPUの内部の意図で、受け取る意味を変えません。

### 11.2 ペナルティDouble（PENALTY-HIGH）

- 敵の**自然な4レベル以上のスートの契約へのDouble**を、守備によるダウンを狙うペナルティの判断の候補として比べます。
- 【CPU基準】自分の守備の札、敵の公開のfit、パートナーの公開戦力から、必要な守備トリックと不足を見積もります。Aなど比較的安定した勝ち札と、K／Qなどの条件付きの勝ち札を分け、長いサイドのAKの2巡目にはラフのリスクを課します。Aも絶対に保証されたトリックとは呼びません。パートナーの初回のPassは協力の期待を下げますが、ゼロにはしません。
- Doubleに、厳密なHCP・守備トリック数・パートナーの応答義務を追加しません。十分確実な4トリックだけを必要条件にせず、Passの利益・危険と相対的に比べます。
- **低いレベルのDouble、テイクアウト、人工の契約へのDoubleの意味は【未定義】です。** これらを高い自然な契約のペナルティと混同しません。未定義のテイクアウトをCPUが勝手に開始しません。

### 11.3 人工の質問への介入

対象の質問：ステイマン（ST01）とその後続の質問（ST03）、市ヶ谷リフレイン（AF01）、特殊4Mへの4NT質問、ガーバー、プレーン・ブラックウッド。ジャコビー2NTは対象に含まれません（[8章](#8-ジャコビー2nt) の6、【未定義】）。

**(a) 回答の前の相手の数値ビッド**

- 人工の質問の後、回答の前に相手が数値ビッドをしたら、その質問への**回答義務を取り消します**。ビッドの水準が上がるので、元の回答を無条件に強制しません。2♠に限らず、すべての数値ビッドに適用します（`1NT–(Pass)–2♣–(2♦/2♥/2♠/3♣…)`、`4♣–(4♥)` など）。席が回っても同じです。
- 質問は人工のまま。取消の後のPassに、メジャーの否定、戦力の上限、ストッパーなどの保証を追加しません。
- 回答者はPassできます。質問者も、別の義務がなければPassできます。
- 例：`1NT–(Pass)–2♣ ステイマン–(2♠)` では、ST01の指定回答の義務を取り消し、オープナーはPassできます。2♣は人工のままで、Passにメジャーの否定やストッパーの情報はありません。応答者も、別の義務がなければPassできます。3♦を元の2♦の回答の代用にしません。
- 介入の後に元の回答と同じビッドをしても、回答の意味は付きません（未定義の競り合いとして扱う）。介入を越える代用の回答や、新しい人工のDoubleは設けません【不採用】。
- 取消の後の再質問の扱いは【未定義】です。
- 別に発生しているGFと、自然なF1は取り消しません。

**(b) 相手のDouble**

- 人工の質問、またはその回答に相手がDoubleしても、ビッドの水準は上がらないので、**質問と回答の義務を維持します**。
- 回答は、Doubleがないときと同じコールで、同じ意味（総枚数、4枚メジャーの有無など）。回答者の義務は残り、Passは義務違反として記録します。
- 回答の後の質問者の契約の選択も、Doubleがないときと同じです。人工の質問や回答を、Doubleされたまま最終契約にしません。
- 市ヶ谷リフレインの意味と回答義務は、Doubleの後も変わりません。
- Doubleそのものの意味は【未定義】のままです。Doubleした側の手について、保証を追加しません。Doubleで質問の系列を「未対応」にしません。
- **質問側のRedoubleは【未定義】。**

**(c) 回答の後の相手の数値ビッド（市ヶ谷リフレイン、特殊4Mへの4NT質問）**

- A・K・Qの人工の回答の後、質問者の次の手番までに相手が数値ビッドで介入したら、その質問の系列は終わり、その系列に由来する質問者の最終契約の宣言の義務は解除します（[9.5](#95-特殊4mへの4nt質問)、[10.3](#103-質問と回答)）。
- 回答の後の相手のDoubleでは、系列と宣言の義務を維持します（上の (b)）。
- 別に発生しているF1・GFなどの独立した義務は取り消しません。
- 介入の後の自陣のコールに、新しい意味や保証を与えません（【未定義】）。
- 人間の合法なコールは、引き続きすべて選べます。

### 11.4 自然なF1への介入

対象の義務：自然なF1（R1・R01・R02・REVERSE・SECOND などの「1回はPassできない」義務）。

**(a) 自然な初回応答の直後の相手の数値ビッド**

- 対象：自然な1スートのオープニング–(Pass)–R1／R01の応答–(相手の数値ビッド)、オープナーの初回の再ビッドの前だけ。オープニングの前のPassに関する適用条件は変わりません。
- 該当のR1／R01がオープナーへ作った**F1だけ取り消します**。オープナーはPassできますが、自然な候補と比べられます。R01のまだ発生していないR02の予約も取り消し、後の任意の再ビッドで復活させません。
- すでに別に発生しているF1・GF・R02は保持します。質問回答義務は [11.3](#113-人工の質問への介入) に従います。
- 取消は回答の履行ではありません。Passに、戦力の上限・短さ・ストッパーの保証を追加しません。相手の数値ビッドの自然／人工を仮定しません（相手の既出スートの2♦の例を含む）。

**(b) 相手のDouble、または (a) にあたらない数値ビッド**

- 相手のDoubleでは、義務を維持します（Passは義務違反として記録）。
- 介入（Double、または (a) にあたらない数値ビッド）の後は、自陣のコールの意味は【未定義】になります。このとき、義務のある席が数値ビッドをしたら、そのこと自体で義務を履行したものとします（「1回はPassしない」という義務の内容を満たすため）。
- 履行になるのは数値ビッドだけ。Redoubleは履行になりません。
- 履行したコールに、意味・枚数・戦力の保証は追加しません（未定義のまま）。
- 質問への回答義務（[11.3](#113-人工の質問への介入)）とGF（[2.6](#26-gf中の終局)）には適用しません。GFは、自然なゲーム契約でだけ履行します。
- 介入がないときは、定義済みの自然なコール（または新しいF1・GF）だけが履行になります。

### 11.5 介入後の限定自然支持

- 対象：自然な1スートのオープニング–(Pass)–R1の1メジャーの応答–(相手の数値ビッド)–オープナーの、応答のメジャーへの最安の支持だけ。
- 自然、**支持4枚以上**、NF、厳密なHCPの保証なし、新しいGFなし。3枚支持・ジャンプ支持へ広げません。応答のメジャーの4+と合わせ、最低8枚fit。切り札合意を新たに自動で付けるものではありません。

## 12. 未定義・不採用・規約外コール

### 12.1 人間の規約外コール

- 人間は、合法なら規約外のビッド／Passを選べます。人間の実際のコールと、CPUの推奨・仮想の候補は別のデータです。受け取る解釈には実際の履歴だけを使い、推奨で置き換えません。
- CPUは対象の規約を守ります。解釈できない場合は、状態・残っている義務・候補の不足をログに記録し、合法に進行を続けます。フリーズを防ぐためのフォールバックを、規約に適合しているように偽装しません。
- UNDEFINED などでも、自分の手札と既知の公開情報から評価できる自然な候補は比べます。ただし、人工のコールに自然な保証を足しません。Passは、現在の契約の品質、fitの不足、ゲームの逸失、パートナーの再選択の機会、レベルの上昇のコストと比べます。全部の合法な候補を評価したと装わず、実際に比べたもの・除外したもの・未対応のものを分けます。

### 12.2 未定義事項（U01〜U09）

### 12.5 必須の例外処理

未定義の部分があっても、次のことは常に必要です。

- 状態を DEFINED／PARTIAL／UNDEFINED／CONFLICT／UNSUPPORTED で保持する。未定義だからといって新しい意味を作らない。
- 有効な回答が存在する宣言済みの系列では、義務を守る。人工の入口だけを実装して、回答がない状態を有効にしない。
- 人間の逸脱や未対応で優先の候補がなくても、クラッシュ・フリーズ・進行停止にしない。合法なフォールバックと規約適合を区別する。
- 規約の未確定が必要な候補を妨げる場合は、該当の系列を部分対応と明記し、ログに原因を残す。製品全体を「全規約実装済み」と表示しない。
- 独立した義務を忘れず、人間の実際の履歴とAIの推奨を分ける。非公開の他の席のカードで救済しない。

### 13.5 ヒントと記録の原則

- 人工・forcingのコールには、文脈に応じたヒントを必須とします。選択の第1ステップを主とし、ホバーを補助とし、オン／オフできます。共有の解釈から、自然／人工、保証、通常目安、求める回答、残る義務、CPUの実装状態を表示します。意味の説明に加えて、同じAIの推奨・比較した候補・評価の理由を表示できます。推奨は最適解の保証ではありません。他の席の実際のカードや、人間への強制の訂正は使いません。表示の操作だけで乱数・履歴を変えません。
- 人間の手番では、自分の手札・公開履歴・同じ乱数状態によるAIの評価を取得します。オン／オフや表示の回数で乱数を進めません。実際のコールの確定時の判断と同じ結果をログに保存し、人間の実際のコール・推奨・一致／不一致を分けます。候補は実際の比較と除外を区別し、候補ごとに共有の解釈から自然／人工、義務、保証、通常目安を表示します。パートナーの直前の意味と、累積の保証／推定、残る義務、Passの可否も表示します。
- 推奨と違う合法な人間のコールを許可し、後続は実際の履歴だけを読みます。ヒントの表示は他の席の手札を受け取りません。終了の前に、他の席の判断・手札を公開しません。終了後のコピー・ログは同じ評価の記録を使います。GUIでの検証とハーネスでの検証を区別して報告します。
- 終了後の全コピーには、両方のSEED、各席の13枚・HCPと全手番の判断を含めます（52枚の見出しは未追加。[13.2](#132-部分的な実装)）。52枚は人間の終了後の検証専用で、AIの判断の入力に渡しません。全手番の候補・評価点・選択の理由・未評価の理由を追跡できること。
- 質問の系列（市ヶ谷リフレイン、特殊4Mへの4NT質問）の人工の回答は、ヒントでは「人工の回答」とA・K・Qの総枚数で示し、強制性（内部の区別 NF）の「Passできる」を出しません。質問者の義務は「あなたの義務」の行に「最終契約を宣言するか、規約で認められた追加の質問をする。Passは規約外」と出します。系列が終わった後（回答の後の相手の数値ビッドなど）は、この義務を出しません。

### 13.6 実装の管理

- 判断理由と診断（PASS_DIAGNOSTIC、PASS_OUTLOOK、GUARANTEE、CPU_ESTIMATE）の形式を維持します。
- 変更のたびに、回帰テストを全部走らせます（市ヶ谷AIの回帰とゲーム全体の回帰）。意図して挙動を変えたテストは、理由を書いて直します。

### 14.3 IDの注意

- **D02** は、1M と 1m の2行に同じIDを使います。別のIDではありません。
- **D系の番号**：本規約で使う番号は D01、D02、D04、D09 だけです。D03、D05〜D08 は使いません。D08 は実装識別子として、プレーン・ブラックウッドに使われています（規約IDではありません）。
- **R1 と R01** は別物です。R1＝最安の1レベル新スート、R01＝非ジャンプ2/1。
- **J01〜J07**：J01〜J04 は初回応答、J05〜J07 は再ビッドです。
- **F01 と F02** は無関係です（F01＝1M–3NT、F02＝強い自然2への応答）。
- **「D系列」**（FSFのD、[6.4](#64-d系列リバース直後のsouth)）と、D01／D02／D04／D09 は別です。
- 実装識別子 `J0x` は、コードの中で J01〜J03 を組み立てるための形で、それ自体は表示されません。
